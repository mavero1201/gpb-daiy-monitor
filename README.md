# GPB Daily Monitor

Еженедельный мониторинг промо-акций банков в сегменте daily banking.

## Логика

1. Период мониторинга - предыдущая календарная неделя, понедельник-воскресенье.
2. Сначала собирается полный поток публикаций из фиксированного реестра источников.
3. Отбор выполняется отдельно по единым правилам.
4. Акция включается только если подтверждены:
   - релевантность daily banking;
   - цель: привлечение / активность текущих клиентов / cross-sell;
   - вознаграждение;
   - действие клиента;
   - точная дата начала и окончания акции;
   - источник.
5. Если обязательный источник не проверен, система не пишет «акций нет».
6. Каждый запуск сохраняет audit-журнал с причинами включения и исключения.
7. Перед формированием выпуска запускается regression test на контрольной неделе.

## Банки

Газпромбанк, ВТБ, Альфа-Банк, Сбер, Т-Банк, Ozon Банк, Яндекс Банк, ПСБ, Совкомбанк, МТС Банк, ОТП Банк, Wildberries Банк.

## Текущий статус

Telegram-источники собираются с пагинацией за весь недельный период.
Официальные сайты банков подключены отдельным web-collector: он обходит фиксированные страницы, переходит в релевантные карточки/правила, читает HTML и PDF и включает только материалы с подтверждённой датой публикации в мониторируемой неделе.
Дубли между Telegram и сайтом исключаются перед публикацией.
Если обязательный источник не удалось проверить, выпуск не публикуется, а причина сохраняется в audit-журнале.

## Ручной запуск

Actions → Weekly Daily Banking monitor → Run workflow.

Workflow сначала проверяет regression baseline, затем формирует preview и сохраняет audit artifact.

## Проверка и публикация (без автоматической отправки)

1. По расписанию в понедельник запускается `Weekly Daily Banking monitor`.
   Публикация по расписанию отключена: GitHub сохраняет точный preview и audit.
2. Если в публикации банка нет полного периода, поиск продолжается по ссылкам
   на правила и через поиск документов на официальных доменах банка.
   Поисковая выдача - только навигация: даты принимаются исключительно
   из самого официального документа, совпадающего с предложением.
3. Проверить `weekly-monitor-audit` в завершённом GitHub Actions запуске.
   В `preview_*.html` должны быть только подтверждённые акции. Отдельно
   проверить `review_queue_*.csv` и причины исключения.
4. Только после явного согласования запускается отдельный workflow
   `Publish approved Daily Banking digest`. Указать ID проверенного
   запуска `Weekly Daily Banking monitor` и подтвердить флажок
   `confirm_approved_preview`. Публикуется именно файл из выбранного
   артефакта без нового сбора, чтобы условия не изменились между
   согласованием и отправкой.
5. Пустой или неполный preview отправить нельзя. Повторный запуск
   публикации того же артефакта вручную может создать дубликат, поэтому
   не запускать workflow дважды без проверки Telegram.

Важно: новая логика пока тестируется в отдельной ветке. До её
согласования и слияния с main основная автоматизация не меняется.
